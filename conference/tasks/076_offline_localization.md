## 背景（別の環境の会話は共有されないので、ここに書く）
- 修論の範囲：ドローンが撮ったばかりの地図を正とし、その上で人が選んだ地点を効率よく回る。BUNKER には GNSS がなく、位置は「LiDAR（と IMU）で動きを積み上げる」＋「ドローンの地図に重ねて直す」で出す予定。
- 文献では、特徴の少ない所で LiDAR の積み上げは大きくずれる。地図に重ねる直しと、**向きごとの決まりにくさ**（位置合わせの情報行列の小さい固有値）を見るのが大事とされている。
- まず目印の多い Gazebo の世界で動くことを確かめ、目印を減らして砂浜に近づける（11/27 に利用者と決めた）。075 で、世界・地図の点群・センサーの記録を作っている。
- 研究 PC に重い仕組み（ROS のパッケージ）を入れる前に、**pip で入る既存のもの**で、記録からあとで位置を出す（オフライン）。

## 作るもの：`conference/experiments/offline_localization.py`
- 入力：075 の記録（LiDAR・IMU・正解の位置・時刻）と、`reference_cloud.npz`（地図の点群）。075 がまだない間は、下のテストの合成データで作る。
- 使うもの：**KISS-ICP**（`pip install kiss-icp`、LiDAR だけの積み上げ）と **small_gicp**（`pip install small_gicp`、点群の位置合わせ）。版を固定し、`conference/requirements_localization.txt` に書く。どちらもない環境では、この道具だけがはっきりしたエラーで止まり、ほかのテストには影響しないこと。
- 出す位置は 3 通り（比べるため）：
  1. **積み上げだけ**：KISS-ICP。
  2. **地図に重ねるだけ**：各スキャン（または 1m 進むごと）を、前の推定を初めの値にして、地図の点群に small_gicp で重ねる。
  3. **組み合わせ**：積み上げを使い、決まった間隔（走った距離 5m ごと）で地図に重ねて直す。重ね合わせが収束し、情報行列（ヘッセ行列）の小さい固有値が基準を超えたときだけ直す。基準は合成データで決めて、報告に書く（Gazebo の結果を見て変えない）。
- 最初の位置は、正解の位置に**決まったずれ**（海岸に沿う 0.5m・向き 2°）を足して与える（人が地図の上で出発の位置を指すことの代わり）。
- 出すもの：
  - 3 通りの推定の軌跡と、正解との差（絶対の位置の誤差の平均・95% 値・最大、走った距離あたりのずれ）。
  - 重ね合わせのたびの、情報行列の固有値（並進と回転に分けたもの）と、いちばん弱い向き（海岸に沿う／海に向かう／回転）。
  - 時間とともに誤差と固有値を並べた図。

## 守ること・やらないこと
- 既存のファイルの出力はバイト単位で変えない。Gazebo・研究 PC は使わない。ROS のパッケージは入れない。
- 基準（固有値の閾値・5m）は合成データで決め、Gazebo の記録を見て変えない。変えるときは別の節に「あとから変えた」と書く。

## テスト `conference/tests/test_offline_localization.py`（ROS2・Gazebo なしで動くこと。kiss-icp・small_gicp がない環境では飛ばして、そう表示する）
1. 合成の世界（凸凹のある地形と箱）と、知っている軌跡から作った合成のスキャンで、積み上げの誤差が決めた範囲に収まる。
2. 地図への重ね合わせで、ずらした初めの値から正解に戻る。
3. 平らな面だけの合成の世界では、情報行列の小さい固有値が小さくなり、弱い向きが平らな面に沿う向きになる。
4. 組み合わせで、固有値が基準より小さいときは直さない。
5. 既存のテストがすべて通る。
