## 背景（別の環境の会話は共有されないので、ここに書く）
- 走りながらの地図は、0.5m のマスごとに点の中央値で地面の高さを作り、隣との差から傾きを出す。25° を超えると通れない（急斜面）とし、0.5m 膨らませる。**どれくらい確かな高さかは持っていない**。
- 残った課題の `08OB88_-0167` の 5 地点目は、地形をセンサーから作る条件（064 の S・D・G・GD の全 12 回）で、偽の急斜面の膨らませで目標が塞がって「経路なし」になる。
  053 の調べでは、**箱とは関係なく**、隣のマス `(137, 293)` の低い側の高さが本当より 0.15〜0.19m 低く推定され、本当は 20.87° の傾きが 25.28〜26.82° と判断されていた。
- 文献（Fankhauser ら 2018 の、高さに分散と信頼の幅を持たせる地図。STEP の、通れなさを確かさ込みのリスクで扱う考え方。`literature_check_ja.md` で実在を確認）は、
  **高さの確かさを持たせ、25° のしきい値の近くでは、すぐに通れないと決めない**。

## 作るもの（選んだときだけ働く。既定の動き・既存の結果はバイト単位で変えない）
- `--slope-uncertainty none|soft`（既定 `none`＝今まで）。`--map fine`・`--terrain-source sensor` 専用（`prior` では傾きを古い地図から取るので使わない）。
- `soft` のとき：
  1. 各マスの高さの**標準誤差** `σ_h` を、そのマスの地面の点（高さの推定に使った点）から出す：点の高さのばらつき（標準偏差）を √（点の数）で割る。
     点が 1 つ以下のマスは、ばらつきが出せないので `σ_h` = 0.15m とする（前もって決めた値。053 で見た高さの誤差 0.15〜0.19m の下の方）。古い地図の高さのままのマスは `σ_h` = 0（古い地図を確かとみなす）。
  2. 傾きの計算に使う隣のマスの `σ_h` から、傾き（の正接）の標準誤差 `σ_s` を、差分の誤差の伝わり方（独立とみなす）で出す。
  3. **確かな急斜面**：傾きが 25° を超え、かつ「傾きの下側 95%（片側、1.645 × σ）」も 25° を超えるマス。今までどおり通れないにし、0.5m 膨らませる。
  4. **確かでない急斜面**：傾きは 25° を超えるが、下側 95% が 25° 以下のマス。**ハードに通れないにはせず、膨らませもしない**。地形のコストを最大（1.0）にする。
  5. 1.645 と 0.15m は前もって決めた値。結果を見て変えない。
- 傾き停止（`unsafe_tilt`、25°）は変えない（本当の急斜面に入っても、最後の守りは残る）。
- `--obstacle-clearance`・`--steep-clearance`（065、取り込まれていれば）・`--ground-near-obstacle`・`--save-plan-maps`・`--pose-trace` と組み合わせられること。`--save-plan-maps` の記録に `σ_h`・確かでない急斜面のマスを足す。
- `lidar_checks.py`・`lidar_planner.py`・`run_lidar_checks.sh` に通し、manifest に記録する。

## 確かめ方（Python、コミットされた記録だけ。Gazebo なし）
- 053・062 と同じ記録（初回の LiDAR 点群と姿勢、終了時の地図、失敗時の診断の地図があるもの）で、`none` と `soft` を比べる：
  1. **見落としの危険（先に書く）**：本当の急斜面（25° 超）とその 0.5m の余白のうち、**ハードに通れないでなくなったマス**の数（確かでない急斜面になったもの）。そこを通る経路があるか、その長さ。
  2. 偽の急斜面のうち、確かでない急斜面になったマスの数・割合（053 の型ごと）。
  3. `0167` の 5 地点目：`(137, 293)` などのマスが確かな／確かでない急斜面のどちらになるか、目標が通れるようになり経路があるか。点の記録が足りず計算できない場合は、何が足りないかを書く。
  4. 046・047・055 の `goal_cell` の記録で、目標が通れるようになるか。
- 偽の地形で、点が少ないマスの段差（確かでない急斜面になる）と、点が多い本当の急斜面（確かな急斜面のまま）。
