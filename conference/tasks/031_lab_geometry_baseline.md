## 背景（別の環境の会話は共有されないので、ここに書く）
- 修論で「研究室の今のやり方と比べて、私たちの TA*-S が何を良くするか」を示したい。
- 研究室のリポジトリ `hayashilab/bunker_ros2` の一番新しいブランチ `bunker_2`（2026-06-24 更新）では、地図なしのナビゲーションの設定
  `bunker_nav/config/nav2_param_without_map.yaml` が、コストマップに**自作のプラグイン `GeometryLayer` だけ**を使い、経路計画に **Nav2 の NavFn**（`use_astar: false`）を使っている。
  Claude が 2026-11-12 に読み取り専用で読んだ内容（研究室のリポジトリは変えていない。Codex はこのリポジトリを読めないので、以下の説明に従う）：
  - コード：`bunker_nav2_custom_costmap_plugins/src/geometry_layer.cpp`。
  - **高さ**：マスに入った点の高さの**平均**（`computeMeans`）。
  - **傾斜**（`computeSlopes`）：まわり 8 マスのうち値のあるものについて、|高さの差| ÷ 距離（縦横は格子の幅、斜めは 1.41×格子の幅）を足し、その数で割った平均。
    値のある隣が **3 つ以下**なら、そのマスの傾斜は「不明」。
  - **コスト**（`costFormula`）：角度＝atan(傾斜)×57.3。5° 以下は 0（FREE_SPACE）、10° 以下は 0.1×LETHAL、15° 以下は 0.2×LETHAL、20° 以下は 0.5×LETHAL、
    25° 以下は 0.8×LETHAL、**25° を超えると LETHAL（通れない）**。LETHAL は Nav2 の `LETHAL_OBSTACLE`（254）。
  - 設定：格子の幅 0.2m（`dummy_resolution: 0.2`）、`robot_radius: 0.35`、**膨らませる層（inflation）は使っていない**、`allow_unknown: true`。
- 私たちの TA*-S は、傾斜と凸凹から作った連続のコスト（ロボットの大きさで正規化、w=8、α=0.5）に、ロボットの大きさ 0.5m の膨らませを加えたもの。

## 作るもの（新しいファイルだけ。既存のファイル・結果は変えない）
1. `tapp/lab_geometry.py`：
   - `geometry_layer_cost(elev, res)`：上の `GeometryLayer` と**同じ式**で、傾斜と 0〜254 のコスト（不明は別の値）を返す。
     入力の「マスの平均の高さ」には、このリポジトリの地図の高さ（0.5m のマス）をそのまま使う。研究室の 0.2m の格子・点の平均とは違うことを README に書く（格子を作り直して合わせることはしない）。
   - `navfn_cell_cost(costmap)`：NavFn がコストマップの値を、1 マスを通るコストに変える式。**Nav2（Jazzy）の `nav2_navfn_planner` のソース（`navfn.cpp` の `setCostmap` など）を確かめて、その式と定数をそのまま使い、
     ソースの場所（ファイル名・関数名・版）を報告に書く**。覚えている値で書かないこと。通れない値と不明の扱いも、ソースのとおりにする（設定は `allow_unknown: true`）。
   - 経路計画：NavFn は**ダイクストラ法**（`use_astar: false`）。このリポジトリの格子・8 近傍で、上のマスのコストを使った最短経路を求める（ダイクストラでも、同じ最適解になる A* でもよいが、どちらかを書く）。
     NavFn の経路の後処理（勾配をたどる）は再現しなくてよい。その違いを README に書く。
   - 障害物：`GeometryLayer` は傾斜だけを見る。013 の漂着物あり（`debris=True`）のシナリオでは、**すべての方法で同じように**、シナリオの障害物のマスを通れないものにする（膨らませない、研究室の設定どおり）。
     あわせて「障害物をロボットの大きさ 0.35m だけ膨らませた版」も、参考として走らせる（研究室の `robot_radius`。安全の比較を公平にするため）。
2. `experiments/lab_baseline.py`：013 の (B)（点群の砂浜の test 48 か所 × 100m・200m × 漂着物なし・あり、同じスタート・ゴール、`results/real_beach_las/offline.csv` のシナリオ）で、
   **A\*、TA\*-S exact（013 と同じ設定）、研究室の方法（`lab_geometry`）、研究室の方法＋0.35m 膨らませ**を比べる。A* と TA*-S exact の値は、013 の `offline.csv` と一致することを確かめる。
3. 集計（013 と同じ指標）：解けた数、経路長、登った高さ、**急斜面（25° 超）を通った距離**、傾斜の最大値・95% 値、横傾き・縦傾きの 95% 値と最大値、障害物のマスに触れた数、
   計画の時間。私たちのコスト（`mean_cost`・`J`）も出すが、**私たちの指標なので私たちに有利**と表に注記する。中立な指標（急斜面の距離、傾斜・傾きの最大値、障害物との接触、経路長）を先に並べる。
   検定は 013 と同じく、砂浜（48 か所）を単位に Wilcoxon の符号順位検定＋Holm。エネルギーは集計しない。
4. 図：013 と同じ規則で選んだ砂浜（`results/abstract_figure/` の規則 1・規則 2 の 2 か所）で、A*・TA*-S・研究室の方法の経路を重ねた図。

## テスト `conference/tests/test_lab_geometry.py`
1. 平らな地面では傾斜 0・コスト 0。一定の傾き（例：5°・12°・22°・30°）の面で、段階のコストが上の表どおりになる。
2. 隣の値が 3 つ以下のマスは「不明」になる。
3. `navfn_cell_cost` が、報告に書いたソースの式と定数どおりになる（いくつかの値で確かめる）。
4. 通れないマスを経路が通らない。
5. A* と TA*-S exact の値が 013 の `offline.csv` と一致する（数か所で）。
6. 既存のテストがすべて通る。

## 変えないこと
- 既存のファイル・結果・既定値。研究室の式の値（5/10/15/20/25°、0.1/0.2/0.5/0.8、3 つ以下で不明）を変えたり、結果を見て合わせ込んだりしない。
