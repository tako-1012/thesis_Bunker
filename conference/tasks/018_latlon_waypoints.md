# 指示書 018：本物の砂浜の地図を緯度・経度と結びつけ、Web 画面で地点を緯度・経度で扱えるようにする

> **状態：未着手**。最初に `AGENTS.md` と `conference/tasks/BATCH_RULES_ja.md` を読むこと。ブランチは `codex/018-latlon`。

## 背景
実機（BUNKER）では GPS（緯度・経度）で位置を扱う。研究室の Android アプリと ROS2 のサービス（`map_point` の `receive_point`、
`float64[] lat, lng`）も緯度・経度を使う。今の地図は平面の座標（m）だけなので、本物の砂浜の地図を緯度・経度と結びつける。

## 作るもの
1. 新しいファイル `conference/tapp/geo.py`（numpy だけ。pyproj などは使わない）：
   ```python
   def plane_to_latlon(X, Y, zone=8) -> (lat, lon)    # 平面直角座標系（X 北、Y 東 [m]）→ 緯度・経度 [度]（GRS80）
   def latlon_to_plane(lat, lon, zone=8) -> (X, Y)
   def map_xy_to_latlon(meta, x, y) -> (lat, lon)     # 地図ファイルの (x, y) [m] → 緯度・経度
   def latlon_to_map_xy(meta, lat, lon) -> (x, y)
   ```
   - 式は国土地理院が公開している平面直角座標系の換算式（ガウス・クリューゲル図法、河瀬の式など）を使い、出典を docstring に書く。
   - 第 8 系の原点は北緯 36°、東経 138°30′、縮尺係数 0.9999。
   - 地図の (x, y) と平面直角座標の関係は、`conference/data_prep/shizuoka_beach_las.py` の `patch_to_plane` と同じ。
     地図ファイルの x・y の原点（最初のマスの中心）と、パッチの (u, v)（中心が 0、u は −100〜100、v は −50〜150）のずれに注意すること。
   - JGD2024 の水平位置は、平面直角座標系の換算では JGD2011 と同じ式・同じ定数で扱う（違いがあれば報告に書く）。
2. 本物の砂浜の地図ファイル（`real_las_*`）に、位置の情報（`origin_xy`、`tangent`、`normal`、系の番号）を加える。
   **今ある地図ファイルは変えずに**、同じ名前の横に `*.geo.json` を置く形にする（`data_prep/export_maps.py` に関数を加えて作る）。
3. Web 画面（`conference/webui/`）：位置の情報がある地図では、
   - マウスの位置（またはタップした地点）の緯度・経度を表示する。
   - 地点のリストを、緯度・経度でも書き出せる（JSON と、1 行に `lat,lng` のテキスト）。読み込みも緯度・経度で受け付ける。
   - 指示書010〜014の API と表示は変えないこと。位置の情報がない地図では、今までどおり。

## テスト：`conference/tests/test_geo.py`
1. 原点：`plane_to_latlon(0, 0)` が (36.0, 138.5) と 1e-9 度以内で一致。
2. **基準値**（Claude が pyproj の EPSG:6676 → EPSG:6668 で計算した値）と 1e-7 度以内（約 1cm）で一致：
   | X [m] | Y [m] | 緯度 | 経度 |
   |---|---|---|---|
   | −146639.066 | −92848.522 | 34.673951199 | 137.486827008 |
   | −146574.980 | −92348.545 | 34.674574079 | 137.492275071 |
   | −146299.598 | −89848.337 | 34.677278811 | 137.519524976 |
   | −150000.0 | −100000.0 | 34.642983539 | 137.409198432 |
   （上の 3 つは `shizuoka_beach_las` の `08OB86_00294`、`08OB86_-0205`、`08OB87_-0206` の `origin_xy` を小数 3 桁に丸めたもの。
   テストでは、この表の X・Y をそのまま使うこと。）
3. 往復：`latlon_to_plane(plane_to_latlon(X, Y))` が 1mm 以内で戻る（静岡の範囲の点をいくつか）。
4. 地図の (x, y) → 緯度・経度 → (x, y) が 1mm 以内で戻る。地図の中心のマスの緯度・経度が、`origin_xy` の緯度・経度と、
   パッチの中心とのずれの分を除いて一致する。
5. Web の API：位置の情報がある地図で緯度・経度が返り、ない地図では今までどおり。
