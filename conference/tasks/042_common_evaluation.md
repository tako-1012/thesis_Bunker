## 背景（別の環境の会話は共有されないので、ここに書く）
- 研究 PC の実験（030・035・037）では、そのたびに研究 PC の担当が集計のスクリプトを作っている。数え方が少しずつ違い（例：経路からのずれの定義、漂着物のマスの数え方）、
  Claude のレビューのたびに定義を確かめ直している。これから 039 段階 B、041 の評価（`centre` と `overlap`）、043（経路を追う側）の評価が続くので、**共通の定義で 1 回で集計できる道具**が要る。
- 041 から、走行の記録に本当の漂着物の箱の形（`debris_footprints` の CSV）と、地図で見つけた障害物までの距離（`clearance.csv`、`--diagnostics` のとき）が残る。
  これを使えば、「0.5m のマスに中心が入った長さ」より、車体が箱に触れたかに近い指標が出せる。

## 作るもの：`experiments/eval_runs.py`
- 入力：1 つ以上の走行の記録のフォルダ（`lidar_checks.py` が作る `physical_*/raw/<砂浜>/` など）と、条件の名前の付け方（フォルダ名からの対応、または対応表の CSV）。
- 出力（`--out` のフォルダに）：
  1. `runs.csv`：1 走行 1 行。今までの 030・035・037 の `runs.csv` の列を含め、定義を 1 つにそろえる。少なくとも次を入れる：
     - 結果（完走・一部・経路なし・止まったまま・転倒・その他の誤り）、回れた地点の数、経路なしの型（`goal_cell`・`start_cell`・`start_steep`・`corridor`・その他）。
     - 安全性：本当に通れないマス・漂着物のマスを中心が通った長さと回数（今までの定義）。**箱の形があるときは、中心から箱までの最短距離（全体の最小、0.5m＝ロボットの半径を下回った時間と回数）**。
     - 地図で見つけた障害物までの最短距離（`clearance.csv` があるとき）。
     - 経路からのずれ：最大・95% 値、ずれが最大になった時刻と場所、そのときの経路の曲がり具合（曲率）。043 の評価に使う。
     - `off_path`・`unsafe_tilt`・傾きのくり返しでの終了（`v2`）の回数と、そのあと計画し直して進めたか。
     - 地図の誤り（誤って通れない・見落とし、023 と同じ定義）、地図の更新の時間（センサー別の中央値・95% 値・最大）、捨てた点群、実測の倍率。
  2. `summary.csv`：砂浜 × 条件ごとに、回数と、各量の最小・中央値・最大（今までの表と同じ形）。
  3. `outcomes_board.csv`：進捗ボードの `conference/progress/outcomes.csv` と同じ列（実験,砂浜,条件,完走,一部,経路なし,止まったまま,転倒）。
  4. `definitions_ja.md`：各列の定義（単位、どの記録から計算したか、ない場合の扱い）。
- 記録が欠けているとき（古い走行で `clearance.csv` や箱の形がないなど）は、その列を空にして理由を残す。黙って 0 にしない。

## 確かめ方
- **今までの集計と同じ数字が出ること**：コミットされている記録（`results/eval_035/runs/`、`results/real_sensors_compare/` など）にツールをかけ、
  030・035・037 の `runs.csv`・表の数字（結果、安全性、`off_path` の回数など、同じ定義のもの）と一致することをテストで示す。違う定義の列は、違いを `definitions_ja.md` と報告に書く。
- 箱までの最短距離・ずれの計算は、答えの分かる小さな偽の記録で確かめる。
- テスト `conference/tests/test_common_eval.py`（ROS2・Gazebo なしで動くこと）。既存のテストがすべて通る。

## 守ること・やらないこと
- 既存の集計のスクリプトと既存の結果は変えない（新しいツールを足すだけ）。走行のコードは変えない。Gazebo は走らせない。
- 判定の閾値（0.5m、0.75m など）は、今までの定義のものを使い、結果を見て変えない。
