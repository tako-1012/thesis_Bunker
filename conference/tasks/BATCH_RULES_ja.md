# まとめて実装するときの共通の決まり（指示書 015〜019）

指示書 015〜019 は、Claude のレビューを待たずに Codex が続けて実装し、あとで Claude がまとめてレビューする。
そのため、各指示書に加えて、次の決まりに従うこと。各指示書の決まりと食い違うときは、各指示書の方を優先する。

## ブランチ
- 各指示書は、**`realtime-map` の最新から**、別々のブランチで作る（`codex/015-...` のように指示書の番号を付ける）。
  前の指示書のブランチの上に作らないこと（指示書どうしは独立している）。
- **マージしないこと。** push までで止める。PR を作れない場合は、報告をリポジトリの中（各指示書が決めた場所）に置く。

## 止まらずに進めるための決まり
- **既存のテストの「ファイルの枚数」などの確認**が、指示書で加えたファイルのせいで落ちる場合は、
  「前からあったものがそのまま残っていること」と「加えたものの数」の両方を確かめる形に直してよい（確かめる中身を弱めないこと）。
  直した場所と理由を報告に書く。それ以外の理由で既存のテストが落ちたら、直さずに報告に書いて止まる。
- **Gazebo・Docker が使えない場合**は、スクリプトとテスト（ROS2 なしで動く部分）まで作り、Gazebo での実行は「未実行」と報告に書く。
  測っていない値を作らないこと（Claude があとで Docker で実行する）。
- 迷ったら、より単純な方を選び、そう選んだことを報告に書く。

## 研究の信頼性（`AGENTS.md` と同じ。とくに大事なもの）
- 本物の砂浜は **`shizuoka_beach_las`（点群のデータ）**を使う。前の `shizuoka_beach` は使わない（0.1m の段々がある）。
- パラメータを決めるときは `validation` の 12 か所（人工の地形ならシード `range(100, 105)`）だけを使う。`test` の結果を見て変えない。
- 結果は実行して得た値だけ。測れなかったものは「未実行」と書く。
- 既存の結果のフォルダ・データ・地図・world は変更しない（各指示書で許したものを除く）。

## 報告（日本語）
各指示書が決めた場所に `REPORT_ja.md` を置く。
1. 実装したもの（ファイル、関数）
2. 実行したコマンドと、テストの出力の全文（`conference/tests/` のすべて）
3. 実験の集計表（そのまま）
4. できなかったこと、自信がないこと、Claude に確かめてほしいこと
