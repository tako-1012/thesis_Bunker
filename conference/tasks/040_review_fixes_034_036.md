## 作るもの

### A. 034 側：`--online-fixes v2`（＝ `v1` ＋次の 3 つ）
`ONLINE_FIXES` に `v2` を足し、`v1` と同じ経路で（`lidar_checks.py`・`lidar_planner.py`・`online_planner.py`・`path_follower.py`）選べるようにする。manifest に記録する。
1. **傾きで止まり続けない（034 の所見 2）**：`unsafe_tilt` で止まって計画し直したあと、**前の `unsafe_tilt` から 10 秒（シミュレーションの時間）以内**に再び `unsafe_tilt` になったら、
   `online_error='unsafe_tilt'` で走行を終える。10 秒は `JOIN_TIMEOUT_S` と同じ値（前もって決めた値。結果を見て変えない）。記録に残す。
2. **長さ 0 の区間で、経路からのずれが計算できなくなる（所見 3）**：ずれの計算で、長さ 0 の区間を除く（点が 1 つだけならその点との距離）。`tapp/pure_pursuit.py`（変更禁止）は変えず、`tapp/online_safety.py` の側で計算する。
3. **ずれを残りの経路で測る（所見 4）**：経路全体ではなく、**今まで進んだ区間から先**の経路との距離で測る（`OnlinePlanner._remaining` と同じ「前にだけ進む」考え方。進み具合は追従側で保持する）。
4. （効率、`v1` と `v2` の両方に入れてよい。ただし `v1` の出力と記録がバイト単位で同じであることをテストで示す）`SafetyOnlinePlanner.observe` が毎回地図全体をコピーしないようにする（観測した範囲だけで、前から見えていて通れたマスが通れなくなったかを調べる）。
5. （読みやすさ）`path_follower.py` で 5 か所にある `getattr(self, 'online_fixes', 'none') == 'v1'` を、初期化で 1 回決める形にまとめる（`v2` も同じ扱い）。`none`・`v1` のふるまいは変えない。

### B. 036 側：テストと小さな直し
6. **窓の大きさのテスト（036 の所見 1）**：1.5m の窓と、それより狭い窓（例：1.1m）とで障害物の判定が変わる偽の点群を作り、今の実装が 1.5m の答えを出すことを確かめる。
   作ったら、窓を 1.1m に変えるとテストが落ちることを、報告に示す。

   走査を何回か重ねて 032 の実装と比べるテストを作る。**通れないマス（lethal）が一致すること**を確かめ、障害物の差のマス数を記録する（差の数は合否に使わない）。
8. **git の履歴に頼らない（所見 3）**：`test_local_speed.py` が `git show` で読んでいる 032 の実装（`local_ground.py`・`pointcloud_map_multi.py` の `5f36770` の版）を、

10. **`--edge-margin-m` で world の作り方を変えない（所見 4）**：`run_checks` で `edge_margin_m` のときに `matched_world` を強制している行をやめる。fine の地図の標準の手順で出力が変わらないことを示す。
