## 背景（別の環境の会話は共有されないので、ここに書く）
- 030 の評価（研究 PC）で、次のことが分かっている。
  - 029（`--ground-estimate non_obstacle`）は効き、安全だった。**今後の標準にする**。
  - 028b（`--endpoint-policy escape_component`）は `08OB88_-0167` で 3 回とも転倒した。**使わない**。
- 033 の原因調べ（研究 PC、`results/diagnosis_033/`）で、走りながら計画し直す仕組みに、次の不具合が見つかった。
  - **A：地点の近くで止まったまま**：ロボット自身のいるマスが（近くの障害物の膨らませで）通れないになると、`_join` がロボットのマスも「通れないマスに触れた」と数えて、新しい経路を毎回はじく。`tick` が計画し直しを強制し続け、走行が上限の時間まで終わらない（`08OB89_-0847` の C1、2 回。保存した地図で再現済み）。
  - **B1：前から見えていたマスが通れなくなっても、計画し直さない**：`OnlinePlanner.update` は、計画し直しの理由（`new_lethal`・`new_cost`）を**初めて見たマス**（`pending_new`）だけで調べる。点が増えて高さが変わり、経路の上の既知のマスが通れなくなっても、古い経路を追い続ける。C2 の転倒の前の 5〜8 秒は、これで新しい経路が作られなかった。**C0・C1 にも同じ弱点がある**。
  - **B3：経路を追う側に、安全のための停止がない**：傾き（roll・pitch）や経路からのずれが大きくなっても止まらない。C2 の転倒では、経路から 1〜2.5m 下へずれて、本当の傾斜 30〜38° に入った。
- 028b の直し（033 の案 2）は、028b を使わないのでこの指示書では行わない。

## 作るもの（**選んだときだけ**働く。既定のふるまい・既存の結果はバイト単位で変えない）
新しい引数 `--online-fixes none|v1`（既定 `none`）で、次の 3 つをまとめて選べるようにする。`v1` は manifest に記録する。
既存のファイル（`online_mission.py`・`lidar_runtime.py`・`online_runtime.py`・`follower.py` など）を直す場合も、`none` では今までと同じ出力になること。新しいファイルで足してもよい。

1. **A の直し**：`_join`（`lidar_runtime.py` の `LidarOnlineMission._join`、`online_runtime.py` の `AsyncOnlineMission._join`、`endpoint_runtime.py` にも同じ処理があればそれも）で、
   **ロボットのいるマスだけ**を、通れないマスの数え方から外す（A* の始点と同じ扱い）。ロボットのマス以外の通れないマスに触れる経路は、今までどおりはじく。
2. **はじかれ続けたときの上限**：`_join` が経路をはじいたことを `plans.csv`（または別の記録）に `join_rejected` として残す。
   **続けて 10 秒（シミュレーションの時間。値は前もって決めたもの）** はじかれたら、`online_error='join_rejected'` で走行を終える（上限の時間まで止まり続けない）。
3. **B1 の直し**：`OnlinePlanner` で、**前から見えていたマスが、通れるから通れないに変わった**ことも記録し（例：`observe` で書き換え前の値と比べて `pending_changed` に貯める）、
   `update` で**残りの経路の上**にそのマスがあれば、理由 `lethal_changed` で計画し直す。計画したら空にする。経路の外のマスが変わっただけなら計画し直さない。
4. **B3 の直し**：経路を追う側（`tapp/follower.py` の `MissionFollower`、`path_follower.py`）で、次のどちらかになったら速度を 0 にして止まり、状態（`unsafe_tilt`／`off_path`）を計画の側と記録に知らせる。
   - |roll| または |pitch| が **25°**（`Robot().max_slope_deg`）を超えた。
   - 経路からのずれが **0.75m**（ロボットの大きさ 0.5m ＋ マスの半分 0.25m）を超えた。
   - 止まったあと、計画の側は今の位置から計画し直す（経路が見つからなければ、今までどおり「経路なし」で終える）。止まったこと・計画し直したことを記録する。
   - 25°・0.75m は、ロボットの仕様とマスの大きさから前もって決めた値。結果を見て変えない。
5. 実行の引数：`lidar_checks.py`・`lidar_planner.py`・経路を追うノードに `--online-fixes` を通す。

## テスト `conference/tests/test_online_safety.py`（ROS2・Gazebo なしで動くこと）
1. `--online-fixes none` では、既存の出力・記録がバイト単位で同じ。
2. A：始点のマスだけが通れず隣が通れる格子で、`v1` なら `_join` が経路を返す（`none` では `None`）。始点の外の通れないマスを横切る経路は、`v1` でもはじかれる。
3. A：保存した実際の状態 `results/diagnosis_033/fixtures/stuck_0847_C1_r2_t1345.npz`（`replay_stuck.py` と同じ手順）で、`v1` なら経路が受け渡される。
4. はじかれ続けると、10 秒（シミュレーションの時間）で `join_rejected` として終わる。
5. B1：既知の通れるマスを経路の上で通れないに変えて `update` を呼ぶと、`v1` では `lethal_changed` で計画し直す。経路の外のマスの変化では計画し直さない。`none` では今までどおり計画し直さない。
6. B3：偽の姿勢・軌跡で、|roll| 26° や経路からのずれ 0.8m で止まり、24° や 0.7m では止まらない。
7. 既存のテストがすべて通る。
