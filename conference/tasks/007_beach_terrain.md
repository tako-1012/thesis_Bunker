# 指示書 007：砂浜と丘の地形を作る（海岸清掃ロボットの想定）

最初に、リポジトリ直下の `AGENTS.md` を読むこと。土台にするブランチは `realtime-map`（最新を取得すること）。
報告・PR の説明・コミットメッセージは日本語で書くこと。

## 背景
BUNKER は、**日本の砂浜で動く海岸清掃ロボット**として使う予定です。修論では、砂浜で、人が地図上で選んだ
複数の地点を、地形を考慮して効率よく回ることを目指します（次の指示書以降）。
指示書006で作った地形（`tapp/natural_terrain.py`）のうち、砂丘・山の斜面・荒れ地は、このロボットの使い方に合いません。
この指示書では、**砂浜の地形**と、**丘（山の斜面をゆるくしたもの）**を作ります。

**既存のファイルは変更しないこと。** すべて新しいファイルに作る。`tapp/natural_terrain.py` の関数は import して使ってよい。

## 地図の向きの約束
- x 軸（配列の 0 番目の軸）を**海岸線に沿う向き**、y 軸（1 番目の軸）を**海から陸への向き**とする。
  y が小さい側が海、大きい側が陸。
- スタートとゴールは、今までと同じく「左の帯（x が小さい）から右の帯（x が大きい）」で選ぶ。
  つまり、**砂浜を海岸線に沿って移動する**場面になる。海（水）と陸側の端の通れない帯には置かない。

## 実装するもの

### 1. 新しいファイル `conference/tapp/beach_terrain.py`
```python
BEACH_TYPES = ("beach_gentle", "beach_steep", "beach_scarp", "rolling", "hills")
def generate_beach(kind, side_m, seed) -> dict
# 返す辞書：{"elev", "rock", "water", "wet", "kind", "side_m", "seed"}
#   water: 水面より低いマス（通れない）、wet: 濡れた砂のマス（満潮線より海側で、水でないマス）
```
乱数はすべて `np.random.default_rng(seed)` から作ること。解像度は 0.5m。

**砂浜の断面（海から陸へ）**。数値の範囲は、文献で報告されている典型的な値の幅として与える。各地図で、範囲の中から一様乱数で選ぶ。
1. **海**：標高が水面（0m）より低いところ。`water` として、通れない場所にする。
2. **前浜**（波が上がる斜面）：海岸線から陸へ、勾配 tanβ で上がる。
   - `beach_gentle`（細かい砂の遠浅の浜）：tanβ ∈ [1/30, 1/15]
   - `beach_steep`・`beach_scarp`（粗い砂の浜）：tanβ ∈ [1/12, 1/6]
3. **満潮線**：標高 h_t ∈ [0.3, 1.0] m。これより低い陸のマスを `wet`（濡れた砂）とする。
4. **バームの頂上**：標高 h_b ∈ [1.0, 2.5] m（ただし h_b > h_t + 0.3）。
5. **後浜**（乾いた砂の平らなところ）：バームの頂上から陸側へ、ゆるく傾く（勾配 1/100〜1/30。陸側へ下がっても上がってもよい）。
6. **陸側の端**：地図の陸側 10〜20% に、海岸の砂丘（植生あり）か護岸の立ち上がりを置く。勾配は 30° 以上で、通れない帯になる。

**海岸線に沿った変化**
- 海岸線の位置、バームの高さ、前浜の勾配は、海岸線に沿ってゆっくり変わる（波長 50m 以上のフラクタル雑音。
  海岸線の位置の振れ幅は ±3m、バームの高さの振れ幅は ±0.3m 程度）。
- **カスプ**（波打ち際の規則的な凸凹）：前浜の上部に、間隔 λ ∈ [15, 35] m、高さの振れ幅 0.1〜0.4m の凸凹を、
  海岸線に沿って並べる（間隔と位相にはばらつきを入れる）。
- **浜崖**（`beach_scarp` だけ）：バームの海側に、高さ 0.5〜1.5m、勾配 45° 以上の段差を置く。
  浜崖は**海岸線に沿って途切れ途切れに**続く（海岸線の長さの 30〜70% にだけ出る。途切れる位置はランダム）。
- **細かい凸凹**：足跡や車の跡を想定して、後浜に標準偏差 2〜4cm の細かい凸凹を足す。濡れた砂は 1cm 程度にする。

**漂着物（障害物）**
- **流木**：満潮線とバームの頂上の間（漂着物がたまる帯）に多く、後浜には少なく置く。長さ 1〜5m、太さ 0.2〜0.5m の線分。
  太さが 0.2m 以上のものは、通れない障害物として `rock` に入れる（指示書006の岩と同じ基準）。
  個数は 100m 四方あたり 5〜20 本（地図の大きさに比例させる）。
- **岩・ごみの塊**：`tapp/natural_terrain.py` の岩と同じ式（Golombek & Rapp）で、k を小さく（0.01〜0.03）して置く。

**丘陵**
- `rolling`：`tapp/natural_terrain.py` の `rolling` と同じもの（import して使う）。比較の基準にする。
- `hills`：`natural_terrain.py` の `mountain` と同じ作り方（フラクタル＋侵食＋崩れ）で、傾斜を**ゆるく**した丘。
  目標（検証用シードの中央値）：傾斜の中央値 8〜11°、25°を超えるマス 1〜5%。

**目標**（検証用シードの中央値）。調整は、検証用シード `range(100, 105)` だけで行うこと。
| 種類 | 目標 |
|---|---|
| `beach_gentle` | 水のマス 10〜30%、濡れた砂 5〜25%、陸側の端の通れない帯以外では 25°を超えるマス 1% 以下 |
| `beach_steep` | 水のマス 10〜30%、25°を超えるマス（陸側の帯を除く）3% 以下 |
| `beach_scarp` | 浜崖のマス（45°以上）が、海岸線の長さの 30〜70% で現れる |

## テスト：新しいファイル `conference/tests/test_beach_terrain.py`（`python3 -m tests.test_beach_terrain` で実行）
1. **決まった結果**：同じ引数で2回作ると完全に一致すること。違うシードでは違う地図になること（5種類、50m）。
2. **断面の形**：`beach_gentle` と `beach_steep` で、海岸線に沿って平均した断面が、海から陸へ
   「水 → 濡れた砂 → 乾いた砂 → 陸側の通れない帯」の順に並ぶこと（100m、シード 100〜104）。
   前浜の平均勾配が、その種類の tanβ の範囲に入ること（±20% の余裕を認める）。
3. **浜崖**：`beach_scarp` で、45°以上のマスが現れる海岸線の割合が 30〜70% に入ること（100m、シード 100〜104 の中央値）。
4. **シナリオ**：`build_beach` が、5種類すべて・50m・シード 0 で解ける地図を返すこと。スタートとゴールが水や通れない場所にないこと。
5. **平滑化**：`run_planner_exact` が、`"TA*-S"` 以外のプランナーで `run_planner` と同じ経路を返すこと。
   `"TA*-S"` の経路が、`path_lethal_cells(path, tm.lethal)` で 0 個であること（5種類・50m・シード 0〜2）。
6. **安全性**：`exact_los=True` の `run_online` で、砂浜の3種類・50m・シード 0〜2、`coarse R5 c10` の条件のとき、
   `path_lethal_cells(traj, tm.lethal)` が 0 個であること。
7. 既存のテストがすべて通ること。
