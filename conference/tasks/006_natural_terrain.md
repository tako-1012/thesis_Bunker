# 指示書 006：自然に近い地形を作り、その上で計画と再計画を確かめる

最初に、リポジトリ直下の `AGENTS.md` を読むこと。土台にするブランチは `realtime-map`（最新を取得すること）。
報告・PR の説明・コミットメッセージは日本語で書くこと。

## 背景
今の地形（`tapp/terrain.py`）は、ICAROB の論文のために作ったもので、自然な地形とは言えません。
- 丘陵：フラクタルをぼかして傾斜を合わせただけ。谷や沢がない
- 尾根：直線の壁と、抜け道が1〜2個。迷わせるために作った形
- クレーター：円形の穴。地球の屋外ではあまり見ない
- 岩場：岩の大きさと数がでたらめ

修論の「走りながらの再計画」は、この地形の上で調べてきました。しかし、たとえば指示書001の大きな改善や、
悪い走行（大回り）は、ほとんどが尾根のマップで起きていました。地形のせいで起きた問題を調べている可能性があります。

この指示書では、**自然の地形の性質に基づいて地形を作る仕組み**を新しく作ります。そのうえで、
(1) 地形の統計が自然らしいことを確かめ、(2) ICAROB の主張（TA\*-S は急斜面を避ける）がこの地形でも成り立つかを確かめ、
(3) 走りながらの再計画が、この地形でどのくらい理想に近いかを調べます。

**`tapp/terrain.py` と `tapp/scenario.py` は変更しないこと**（論文の結果を保つため）。すべて新しいファイルに作る。

## 実装するもの

### 1. 新しいファイル `conference/tapp/natural_terrain.py`
```python
NATURAL_TYPES = ("rolling", "mountain", "badlands", "dunes", "boulders")
def generate_natural(kind, side_m, seed) -> dict   # terrain.generate と同じ形：{"elev", "rock", "kind", "side_m", "seed"}
```
解像度は `tapp.config.RESOLUTION`（0.5m）。乱数はすべて `np.random.default_rng(seed)` から作ること。

**部品**
- **フラクタル地形**：パワースペクトルが `P(k) ∝ |k|^-(2H+2)` になるスペクトル合成。H = 0.8 とする
  （自然の地形のフラクタル次元 D ≈ 2.1〜2.3、すなわち H ≈ 0.7〜0.9 という報告による。Huang & Turcotte 1989 など）。
  `tapp/terrain.py` の `fractal_noise` を import して使ってよい（`beta = 2H+2`）。
- **水による侵食**：水滴を流して土を削り、運ぶ方法（Beyer 2015 "Implementation of a method for hydraulic erosion"、
  Hans Theobald Beyer の学士論文）。谷と沢を自然に作るために使う。
  - 水滴の数、1滴の最大の歩数、削る強さ・置く強さ・運べる量・蒸発の割合・慣性・削る半径は、定数としてファイルの先頭に書く。
  - 速くするために、多数の水滴を numpy でまとめて動かしてよい（`np.add.at` など）。ただし、同じシードで必ず同じ結果になること。
- **崩れ（熱的侵食）**：隣のマスとの傾きが「安息角」を超える分の土を、低い方へ移すことをくり返す。
  安息角は砂丘では 32°、それ以外では 38° とする。
- **岩**：Golombek & Rapp (1997) の、岩の大きさの累積面積の式 `F_k(D) = k · exp(−q(k) · D)`、`q(k) = 1.79 + 0.152 / k`
  （D は岩の直径 [m]、k は岩の多さ）に従って、直径 0.1m 以上の岩を置く。岩の高さは直径の 0.5 倍とする。
  - 直径 0.4m 以上（高さ 0.2m 以上）の岩は、通れない障害物として `rock` に入れる（ロボットの車体の下をくぐれないとみなす）。
  - それより小さい岩は、標高に小さなこぶとして足す（凸凹になる）。

**地形の種類**（数値はあらかじめ決めた目標。テスト用シードの結果を見て変えないこと）

| 種類 | 作り方 | 目標（検証用シードの中央値） |
|---|---|---|
| `rolling`（草地の丘陵） | フラクタル（起伏小）＋弱い侵食 | 傾斜の中央値 4〜7°、25°を超えるマス 2% 以下 |
| `mountain`（山の斜面） | フラクタル（起伏大）＋強い侵食＋崩れ | 傾斜の中央値 12〜18°、25°を超えるマス 8〜20% |
| `badlands`（侵食された荒れ地） | フラクタル（細かい起伏が多い）＋とても強い侵食＋崩れ | 傾斜の中央値 12〜20°、25°を超えるマス 10〜25% |
| `dunes`（砂丘） | 風下側が急（安息角）、風上側がゆるい（5〜12°）、非対称な砂の山を並べ、尾根の線をフラクタルで曲げる。崩れ（32°）を最後にかける | 25°を超えるマス 8〜25% |
| `boulders`（岩の多い平地） | `rolling` と同じ地形＋岩（k = 0.10） | `rock`（膨らませる前）が地図の 0.5〜5% |

- 目標に合わせる調整（起伏の大きさや侵食の強さ）は、**検証用シード `range(100, 105)` だけ**で行うこと。
  決めた値は定数としてファイルに書き、PR に調整の経過を書くこと。
- どの地形も、地図の大きさ（50・100・200m）で傾斜の統計が大きく変わらないようにすること
  （`terrain.py` の `relief` と同じく、傾斜の中央値で大きさを合わせる方法でよい）。
- 1枚の地図を作る時間は、100m で 30 秒以内、200m で 120 秒以内を目安とする（超えた場合は PR に書く）。

### 2. 新しいファイル `conference/tapp/natural_scenario.py`
```python
def build_natural(kind, side_m, seed, weights=CostWeights(), robot=Robot(), max_tries=20) -> dict
```
`tapp/scenario.py` の `build` と同じ手順・同じ形の辞書を返す（スタートとゴールの選び方、`astar(tm.lethal, s, g)` で
解けるまで作り直すこと、`redraws` の記録も同じ）。シードの作り方は `np.random.SeedSequence([seed, 1000 + 種類の番号, side_m, k])`
とし、今の地形と重ならないようにする。`run_planner` は `tapp/scenario.py` のものをそのまま使える。

### 3. 実験スクリプト `conference/experiments/natural_terrain.py`
結果は `conference/results/natural_terrain/` に置く。

**(A) 地形の統計**（検証用シードとテスト用シードの両方。統計の表示であって、調整には使わない）
種類ごと・大きさ（50・100・200m）ごとに、次の中央値を表示する。
傾斜の 50・90・99% 値、25°を超えるマスの割合、`rock` の割合、凸凹（`rough`）の中央値、
動径平均したパワースペクトルの傾き（侵食の前と後）、作り直しの回数、作るのにかかった時間。
また、種類ごとにシード 100・100m の地図を、陰影図と傾斜図（25°以上を赤）で並べた図を
`natural_terrain_gallery.png` として保存する。

**(B) ICAROB の主張の確認**（テスト用シード `range(10)`、大きさ 50・100・200m、5種類すべて）
`tapp.scenario.PLANNERS` の5つのプランナーを `w=DEFAULT_W` で実行し、`run_all.py` の本実験と同じ指標を記録する。
表示する集計：プランナーごとの急斜面を通った割合、`steep_len` の中央値、地形コスト、登った高さ、エネルギー、経路長、
計画時間（中央値）。TA\*-S と A\* の差については、`experiments/analyze.py` の `paired_test` と `holm` を使って検定する。
また、`tapp.collision.path_lethal_cells` で、TA\* と TA\*-S の経路が通行禁止のマスに触れた数を表示する。

**(C) 走りながらの再計画**（テスト用シード `range(10)`、大きさ 50・100m、5種類すべて）
共通の設定は、`planner="TA*-S"`、`w=DEFAULT_W`、**`exact_los=True`**、`prior_lethal="soft"`。

| 名前 | 設定 |
|---|---|
| `oracle TA*-S` | 地図をすべて知っている |
| `oracle A*` | エネルギーの基準 |
| `online adaptive R15` | 粗い地図なし、`unknown_cost="adaptive"`、R=15m |
| `coarse R15 c5` | `coarse_prior(tm, 5)`、R=15m |
| `coarse R10 c10` | `coarse_prior(tm, 10)`、R=10m |
| `coarse R5 c10` | `coarse_prior(tm, 10)`、R=5m |
| `coarse R5 c20` | `coarse_prior(tm, 20)`、R=5m |

表示する集計は、指示書003の `risk_prior_log.txt` と同じ構成にする（中央値、dJ と dL の 90% 値と最大値、地形の種類別の dJ の中央値、
失敗の一覧）。それに加えて、通行禁止のマスに触れた走行の数（`path_lethal_cells`）を表示する。
**dJ が 25% を超えた走行の一覧**（種類、大きさ、シード、条件、dJ、dL、再計画の回数）も表示する。

並列化には `multiprocessing.Pool` を使う。

## テスト：新しいファイル `conference/tests/test_natural_terrain.py`（`python3 -m tests.test_natural_terrain` で実行）
1. **決まった結果**：同じ引数で2回作ると、`elev` と `rock` が完全に一致すること（5種類、50m、シード 100）。
   違うシードでは違う地図になること。
2. **大きさと値**：`elev` の大きさが `round(side_m / RESOLUTION)` 四方であること。NaN や無限大がないこと。
3. **スペクトル**：侵食をかける前のフラクタル地形（関数を分けておくこと）の、動径平均したパワースペクトルの傾きが、
   `−(2H+2)` から ±0.3 以内であること（128×128、シード 0〜4 の平均）。
4. **岩**：`boulders` で、置いた岩の直径の分布から計算した累積面積が、`F_k(D)` と大きく違わないこと
   （D = 0.4, 0.6, 1.0m で、相対誤差 30% 以内。100m の地図5枚の合計）。
5. **シナリオ**：`build_natural` が、5種類すべて・50m・シード 0 で、スタートからゴールまで `astar(tm.lethal, ...)` で
   解ける地図を返すこと。`build_natural` の結果を `run_planner("TA*-S", ...)` に渡すと成功すること。
6. **安全性**：`exact_los=True` の `run_online` で、5種類すべて・50m・シード 0〜2、`coarse R5 c10` の条件のとき、
   `path_lethal_cells(traj, tm.lethal)` が 0 個であること。
7. 既存のテストがすべて通ること。
