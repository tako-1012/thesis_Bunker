## 背景（別の環境の会話は共有されないので、ここに書く）
- 修論の範囲（11/26 に決めた）：ドローンが撮ったばかりの地図を正とし、その上で人が選んだ地点を効率よく回る。
- BUNKER には **GNSS がない**。IMU と LiDAR はある。履帯なので、車輪の回転による移動量は砂の上で当てにならない。
  そのため、位置は「LiDAR と IMU で動きを積み上げる」＋「ドローンの地図に重ねて直す」で出すことになる。
- 心配：砂浜は特徴が少なく、特に**海岸に沿った向き**のずれが決まりにくいかもしれない。ただし、遠くの砂丘・浜の段差・護岸・岩などが見えれば決まる。
- ドローンの点群の地図は、研究室からあとでもらう予定。それまでは、手元の静岡の LAS の標高（62 枚、各 200m 四方、0.5m のマス、`tangent` が海岸に沿った向き、`normal` が海に向かう向き）を「ドローンの地図」の代わりに使う。

## 作るもの：`conference/experiments/localizability_map.py`
各砂浜で、ロボットが立てる場所（陸で、急斜面でない所）に 5m おきに点を置き、各点で次を出す。
1. **見える範囲の切り出し**：その点から半径 R の円の中の標高（R は **20m と 40m** の 2 通り。前もって決める。LiDAR の機種が分かったら別に足す）。
   `visibility.py` に見える・見えないの計算があれば使い、隠れて見えないマスは除く。なければ円の中をすべて使い、そのことを報告に書く。
2. **ずらしたときの違い**：切り出した標高を、その場所の地図に対して ±3m（0.5m きざみ）・±10°（2° きざみ）ずらし、重なった所の高さの差の二乗平均を出す。
   **高さの全体のずれは消してから比べる**（ドローンの地図とロボットの地図で高さの基準が違ってもよいように、重なった所の平均を引く）。
   ずらしは、`tangent`（海岸に沿う）・`normal`（海に向かう）の 2 軸と、回転で行う。
3. **決まりやすさ**：
   - ずれ 0 のまわりの曲がり方（二乗平均の 2 階微分から作る 3×3 の行列）の固有値と、いちばん小さい固有値の向き（海岸に沿う／海に向かう／回転のどれに近いか）。
   - **まぎらわしさ**：ずれ 0 から 1m 以上離れた所で、二乗平均がずれ 0 の場合 ＋ 高さの雑音の分（σ = 0.05m とする。前もって決める）を下回る所があるか。あれば「位置が決まらない」とする。
4. 砂浜ごと・R ごとの集計：
   - 位置が決まらない点の割合、海岸に沿った向きだけが決まらない点の割合。
   - 決まる点どうしが、海岸に沿ってどれだけ離れているか（最大・中央値）。動きの積み上げだけで走る区間の長さの目安になる。
   - 地図の図（各砂浜で、決まりやすさを色で塗る。決まらない向きを短い線で示す）。

## 守ること・やらないこと
- 値（5m おき、R = 20・40m、±3m・±10°、σ = 0.05m、1m）は上のとおり。結果を見て変えない。足すときは別の節に「あとから足した」と書く。
- 既存のファイルの出力はバイト単位で変えない。Gazebo・研究 PC は使わない。
- これは「標高だけを重ねる」簡単な見積もりで、本物の自己位置推定（LiDAR 慣性オドメトリ・点群のマッチング）ではない。報告でもそう書く。
- 0.5m のマスでは小さい岩は写らない。ドローンの地図の方が細かければ、この見積もりは厳しめになる（報告に書く）。

## テスト `conference/tests/test_localizability_map.py`（ROS2・Gazebo なしで動くこと）
1. 海に向かってだけ傾いた、海岸に沿ってまったく同じ形の地形で、海岸に沿った向きが「決まらない」と出る。
2. 円錐の山（どの向きにも形が変わる）で、位置が決まると出る。
3. 同じ形の山が 2 つあり、その間隔がずらしの範囲に入る地形で、「まぎらわしい」と出る。
4. 高さの全体のずれ（＋1m）を足しても結果が変わらない。
5. 既存のテストがすべて通る。
