## 結論
- **道具として取り込む。ただし「位置が決まらない点 73%」という数字は使わない。**
  - この数字は、指示書（Claude が書いた）で決めた判定のしかたで、ほぼ決まっている。判定を変えると 0% にも 80% にもなる（下の「あとから足した確かめ」）。
  - 使えるのは、**場所どうしの比べ**（どこが弱いか、どの向きが弱いか）と、道具の仕組み（見える範囲・ずらし・曲がり方）。
- 正しく見積もるには、**本物の誤差の入り方**が要る。研究室のドローンの地図が LAS と同じ砂浜を写していれば、2 つの地図を重ねてみるのが一番の材料になる。

4. **中心の差分を読んだ**：
   - 見える範囲は `visibility.py` と同じ光線で、隠れたマスを除いている。
   - 高さの全体のずれは、重なったマスの平均を引いて消している。
   - 格子の 0 番目の軸が海岸に沿う向き、1 番目の軸が海から陸への向き（`data/shizuoka_beach_las/README_ja.md`）で、ずらしの向きと合う。

5. **わざと壊す**：「決まらない」の判定から雑音の分（σ²）を外す（`far < base + σ²` → `far < base`）→ テスト 1（海岸に沿ってまったく同じ形の地形）とテスト 3（まぎらわしい地形）が検出した。
6. **数字の出し直し**：`08OB88_-1417` を走らせ直し、`summary.csv` の行は完全に一致した。点ごとの配列も、分類は同じで、浮動小数の差は 1e-16 程度（計算機の違い）。

## あとから足した確かめ（集計の前には決めていなかった）
`review_criterion.py`（出力 `review_criterion_log.txt`）。60 枚 × 2 つの半径の 120 行。

- 071 の判定：「1m 以上ずらした所の、高さの差の**二乗平均**が σ²（σ = 0.05m）だけしか増えなければ決まらない」。
  - **点の数を考えない**ので、見える範囲が広いほど平らな砂で薄まり、「決まらない」が増える。半径 40m の方が 20m より決まらない砂浜があるのはこのため（例：`08OB86_00294` で 77% → 87%）。
- 比べた判定：「その差に重なったマスの数を掛けた**和**が 9σ² に届かなければ決まらない」（マスごとにばらばらな雑音だけを考えた場合）。
  - **120 行すべてで 0%**（重なったマスは 4,000〜12,000）。
- どちらも極端：
  - 071 の判定は厳しすぎる側（たくさんの点の情報を、1 点分としてしか数えない）。
  - 比べた判定は甘すぎる側（同じ地図どうしを重ねていて、地図の誤差（ドローンの DEM で約 20cm）や砂の変化など、マスどうしでつながった誤差を入れていない）。
  - 本当の答えはその間にあり、**誤差の入り方を決めないと数字は出せない**。

## これからに向けて
- 判定は、文献にある「情報行列（ヘッセ行列）の小さい固有値」を、**本物に近い誤差**（地図どうしの違い、点群のにじみ）で比べる形に直すのがよい。
- ドローンの地図が届いたら、LAS と重なる砂浜があるかを確かめる。あれば、2 つの地図の違いが「つながった誤差」の大きさの材料になる。
