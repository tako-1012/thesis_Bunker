# hayashi_rtf_repeat：08OB87_-0706 の反復試験（目標倍率 1.0 と 0.3）

## 目的
研究PCの初回試験で `08OB87_-0706`（0.3倍）が `no_path` になった（クラウド023は completed）。
同じ条件を繰り返し、`no_path` が倍率と関係するのか、実行ごとの違いなのかを切り分ける。
これは手順の変更を決める試験ではない。次の段階（1.0倍で3か所）へ進んでよいかを決める。

## 条件（結果を見る前に確定、2026-11-07）
- 変えるのは `real_time_factor` だけ（1 または 0.3）。各3回、計6回。
- 実行順は固定の交互：1→0.3→1→0.3→1→0.3。機械の状態の変化が片方の倍率に偏らないようにするため。
- その他は `hayashi_rtf1_check` と同じ：`--map fine`、stale 1.0秒、ソフトウェア描画、同じイメージ、同じ overlay、同じ計測。
- `gz sim --seed 0` は全回同じ。結果の違いが出れば、乱数の種ではなく実行のタイミングなどに由来する。
- 外側の時間上限は1回2400秒（0.3倍の完走に約1530秒必要なため、前回の1500秒から変更。倍率によらず同じ値）。
- 既存の結果は参照のみ。`first_0.3`（初回試験、probe なし）は3回の数に含めず、別に示す。

## 判定基準（結果を見る前に確定）
**A. 実行の有効性（各回）**：`simulation.ok` と `measurement.ok` が true、実測倍率が目標の ±1% 以内、
`queue_drops` と地図の誤りが 0。満たさない回は結果の比較から除き、理由を書く。

**B. `no_path` の扱い（有効な回の記述のみ）**：3回ずつでは統計的な差は言えない。回数だけを示す。
| 結果 | 読み方 |
|---|---|
| 両方の倍率で `no_path` が出る | 倍率に固有ではない。実行ごとの違いとして原因調査へ |
| 0.3倍でだけ出る | 1.0倍が悪いとは言えない。ただし倍率の影響の有無は未確定 |
| 1.0倍でだけ出る | 1.0倍の懸念として扱い、次の段階へ進まない |
| どちらも出ない | 初回の `no_path` は再現せず。probe の有無などの違いも記録する |

**C. 1.0倍の処理の余裕（有効な回）**：更新が周期を超える割合 1% 以下、`/cmd_vel` 19Hz 以上（シミュレーション時間）、
点群の古さの最大が stale 1.0秒（シミュレーション時間）未満。

**次の段階へ進む条件**：1.0倍の3回がAとCを満たし、1.0倍の `no_path` の回数が0.3倍以下のとき。
進まない場合は、記録から原因を調べる。

## 集計の注意
軌跡の距離は「各点から相手の軌跡の最も近い点まで」を両方向で集めた値（`summarize_repeat.py`）。
`hayashi_rtf1_check/trajectory_gaps.csv` とは定義が違うため、値は同じにならない（例：同じ2本で最大14.45mと16.44m）。

### 事前の基準に沿った判定
- **A：1倍の3回は `queue_drops` が 0 でないため、無効。** 基準どおり `no_path` の回数の比較からは除く。
  結果を見たあとで基準を緩めることはしない。
- **B：有効な回（0.3倍の3回）で `no_path` は 0/3。** 表の「どちらも出ない」には、1倍が無効のため厳密には当てはまらない。
  参考として、無効とした1倍の3回も全部 completed だった。初回の `no_path` はこの6回では再現していない。
  初回との違いとして、この6回には probe があり、初回にはない。
- **C：1倍は満たさない。** 更新が周期を超える割合が 1.43〜2.07%（基準は1%以下）。`/cmd_vel` と点群の古さは基準を満たす。
- **次の段階へ進む条件は満たさない。** 1倍で3か所に広げる判断はできない。

### 読み方の注意
- `queue_drops` の基準を 0 としたのは事前の決定だが、クラウド正式の同じ走行でも 1 ある。今回の 15〜27 は受信約4200回の 0.4〜0.6%。
  走行が失敗したわけではないが、地図の更新が追いつかない場面が1倍で実際に起きている。
- 全回が completed でも、経路の形は回ごとに最大 7.33m 違う（`trajectory_gaps.csv`）。
- `no_path` の原因調査は `rtf_check/divergence/` に続く（026）。
