# 本物の砂浜の地形データ（点群から作り直した版）

`conference/data/shizuoka_beach/` と**同じ 60 か所・同じ位置・同じ向き**の砂浜を、静岡県の ALB の**地面の点群**から作り直したデータです。
`split`（`validation` 12 か所、`test` 48 か所）も同じです。

## なぜ作り直したか
`shizuoka_beach/` の元にした ALB の 0.5m グリッドデータは、**標高が 0.1m 単位に丸めてあります**
（確かめた図郭 08OC9382・08OC9393 では、すべての値が 0.1m の倍数でした）。
そのため、ゆるやかな砂浜が 0.1m の段々になり、段の上では傾きが 0、段の境（0.5m で 0.1m）では約 11° に見えていました。
Gazebo で BUNKER を走らせたとき、傾きがちょうど 0 になる区間が続いたことで気づきました
（`conference/ros2_jazzy/gz_checks/results/claude_docker_run/README_ja.md`）。
同じ測量の地面の点群（LAS）は 1mm 単位で、0.5m のマスあたり中央値 7 点あるので、そこから標高を作り直しました。

## 出典とライセンス
- 出典：静岡県「VIRTUAL SHIZUOKA 静岡県 中西部沿岸 点群データ」ALB 地面の点群（Ground）
  https://www.geospatial.jp/ckan/dataset/shizuoka-2025-pointcloud-alb
- ライセンス：CC BY 4.0 / ODbL。**このフォルダのデータは、上のデータを加工して作成したものです。**
- 元データの座標：日本測地系2024・平面直角座標系第8系、高さは東京湾平均海面（T.P.）。

## 1つのファイルの中身（`<図郭>_<位置>.npz`）
| キー | 内容 |
|---|---|
| `elev` | 標高 [m]（float32、400×400、0.5m 間隔）。NaN はデータのない場所 |
| `npts` | そのマスに入った地面の点の数（uint16） |
| `origin_xy`、`tangent`、`normal`、`res` | `shizuoka_beach/` と同じ値（位置と向き） |

配列の向き（0 番目の軸が海岸線に沿う向き −100〜100m、1 番目の軸が海から陸への向き −50〜150m）も `shizuoka_beach/` と同じです。

## 作り方
`conference/data_prep/shizuoka_beach_las.py` で再現できます（静岡県のデータを置いている S3 にアクセスできる環境が必要）。
1. 各パッチがかかる図郭（300m × 400m、全部で 147 個）の地面の点群をダウンロードする。
   そのうち 8 個は測量の範囲外でファイルがない（公開グリッドにもない）。
2. 点をパッチの向きに回し、0.5m のマスごとに平均する。
3. 点のないマスは、まわり 3×3 マス（1.5m 四方）の点の平均にする。それもなければ NaN。

## 前のデータとの違い（60 か所）
| | 前のデータ（`shizuoka_beach/`） | このデータ |
|---|---|---|
| 0.1m の倍数のマスの割合（中央値） | 約 50%（陸） | 0.2% |
| 前のデータとの差（このデータ − 前） | — | 平均 +1.2cm、標準偏差 5.1cm（パッチごとの値の平均） |
| データのない割合（平均） | 13.1% | 14.0% |
| 陸の幅の中央値（平均） | 124.5m | 125.1m |

- 前のデータとの差の標準偏差（3〜11cm）には、0.1m への丸め（標準偏差 2.9cm）が含まれます。
- **11 か所で、沖側（y < −30m）にデータのないマスが増えました**（深い所は地面の点が少ないため。前のグリッドは補間で埋めていた）。
  そのため、`shizuoka_beach.py` の `good_patch` の「沖側の NaN が 10% 以下」という条件は満たさなくなりましたが、
  海は元々通れない扱いなので、ロボットの計画には影響しません。陸側（y ≥ 0）のデータのない割合は、前とほぼ同じです
  （中央値 17.2%、前は 17.7%）。60 か所をすべてそのまま使います。
- 12 か所で比べると、陸の凸凹（`rough`）の中央値は 1.95cm → 0.89cm、地形コストの中央値は 0.195 → 0.121 に下がりました。
  通れない陸の割合は 1.8% のままです。段々が、平らな所の凸凹とコストを実際より大きく見せていたことになります。

`index.json`：各パッチの名前、座標、`split`、かかる図郭、上の表の値（パッチごと）。
