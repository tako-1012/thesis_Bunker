# 本物の砂浜の地形データ（静岡県・遠州灘）

修論の実験で使う、**本物の砂浜の標高データ**です。静岡県が公開している航空レーザ測深（ALB）の 0.5m 格子データから、
砂浜を 200m 四方で 60 か所切り出しました。

## 出典とライセンス
- 出典：静岡県「VIRTUAL SHIZUOKA 静岡県 中西部沿岸 点群データ」ALB グリッドデータ（0.5m）
  https://www.geospatial.jp/ckan/dataset/shizuoka-2025-pointcloud-alb
- ライセンス：CC BY 4.0 / ODbL。**このフォルダのデータは、上のデータを加工して作成したものです**
  （論文や発表で使うときは、この出典を書くこと）。
- 元データの座標：日本測地系2024・平面直角座標系第8系、高さは東京湾平均海面（T.P.）。

## 範囲
遠州灘の砂浜（西は湖西市から、東は掛川市付近まで。東経 137.49°〜138.07°）。

## 1つのファイルの中身（`<図郭>_<位置>.npz`）
| キー | 内容 |
|---|---|
| `elev` | 標高 [m]（float32、400×400、0.5m 間隔）。**NaN はデータのない場所**（主に陸側の測量範囲の外） |
| `origin_xy` | 切り出しの中心の座標（平面直角座標系第8系の X, Y [m]） |
| `tangent`、`normal` | 元の格子での、海岸線の向きと、陸への向き |
| `res` | 0.5 |

- 配列の 0 番目の軸（x）が**海岸線に沿う向き**（−100〜100m）、1 番目の軸（y）が**海から陸への向き**（−50〜150m）。
  `tapp/beach_terrain.py` の人工の砂浜と同じ向きにしてある。
- 海岸線は、標高 0m（T.P.）の線とした（測量した時刻の水際とは一致しない）。

`index.json`：各ファイルの名前、中心の座標（おおよその緯度経度）、データのない割合、陸の幅の中央値、最高標高、
25° を超える陸の割合、`split`（`validation` が 12 か所、`test` が 48 か所）。
**パラメータの調整は `validation` だけで行うこと**（`AGENTS.md` のシードの決まりと同じ考え方）。

`preview.png`：一部の陰影図（青線が海岸線）。

## 作り方
`conference/data_prep/shizuoka_beach.py` で再現できる（静岡県のデータを置いている S3 にアクセスできる環境が必要）。
1. 遠州灘の図郭（08OB8*、08OC*、08PC*、08PD0*、08PD1*）の 0.5m 格子データをダウンロードする。
2. 陸（標高 0m より高い所）のうち一番大きなつながり（本土の砂浜）の海岸線だけを使う（離岸堤や突堤の先を除くため）。
   海岸線に沿って 250m ごとに、前後 ±100m の海岸線の向き（主成分分析）を求め、海岸線に沿う向きと陸への向きで
   200m 四方を双線形補間で切り出す。海岸線の位置の中央値が y = 0 になるように、もう一度ずらして切り出す。
   データのないマスに触れるところは NaN にする。
3. 次の条件をすべて満たすもの（170 か所のうち 137 か所）から、西から東へ等間隔に 60 か所を選ぶ。
   - 海側（y < −30m）と砂浜（y = 0〜50m）が測量されていて、海側の平均標高が 0 未満、y = 0〜50m のどこかが 0 を超える（海と陸の向きが正しい）
   - 80% 以上の列で、海岸線が y = 0 から ±15m 以内にある
   - データのない割合が 30% 未満で、陸の幅の中央値が 60m 以上
   5 か所に 1 か所（番号を 5 で割った余りが 2）を `validation` にする。
保存したデータは、このスクリプトの出力そのものである。

**改訂履歴**：最初の版（PR #28）では離岸堤・突堤の海岸線を本土の海岸線と取り違え、海と陸の向きや海岸線の位置が
ずれたパッチが 11 か所あった（指示書009のテストで見つかった）。上の 2・3 の処理を加えて作り直した。

## 注意（このデータでわからないこと）
- 漂着物（流木・ごみ）の位置、濡れた砂と乾いた砂の区別、植生はわからない。
- 陸側の測量範囲が途中で切れている場所がある（NaN）。経路計画では、通れない場所として扱う。
- 測量した日は、元データの説明では個別に示されていない（2024〜2025 年度ごろ）。
