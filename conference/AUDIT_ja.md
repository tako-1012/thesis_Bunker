## 1. 卒論で見つかった問題（国際学会に出す前に必ず対応が必要）

### 1.1 実測ではない数値が「実験結果」として使われている
| 本文中の箇所 | 元になっているスクリプト | 問題 |
|---|---|---|
| 第3章 表（α,β,γ の調整結果） | `scripts/parameter_tuning_alpha_beta.py` | 「要件に合わせた結果を生成」と書かれ、経路長と地形コストが辞書に直接書き込まれている。地形も `np.random.randn` のダミー |
| 第4章 図（w_t の調整）、「地形コスト40.3%削減」「経路長+19.7%」「約9秒」 | `scripts/parameter_tuning_wt.py` | プランナーを一度も実行していない。w_t=1.0 の「既知の値」から式で値を作っている |

→ 2つのスクリプトは、実行すると止まるようにしました（中身は残してあります）。
`results/README_INVALID.md` にも注意書きを置きました。
**投稿済みの原稿にこれらの数値が入っている場合は、指導教員に相談のうえ訂正してください。**

### 1.2 統計値が自分の表と矛盾している
- 第6章「TA* vs AHA* 経路長: t=−2.34, p<0.001, d=0.91」に対し、`tables/table6_4_statistical_tests.md` は t=−0.250, p=0.803, d=−0.04。
  そもそも t=−2.34, df=189 なら p≈0.02 で、「p<0.001」にはならない。
- 第6章「Field D* Hybrid vs Theta* 計算時間: t=−3.42, p<0.001」に対し、表は t=0.982, p=0.327。
- Field D* Hybrid の計算時間は、本文が 0.175 s、表1 が 0.4947 s。

### 1.3 実験設定の記述が、コードやデータと合っていない
- 第5章「Perlinノイズで丘・谷、障害物10〜30個」→ 実際の地形は「定数＋N(0, 0.02)」だけで、丘も障害物もない（`scripts/run_fieldd_96_benchmark.py`）。
- 「Small/Medium/Large 各32」→ 実データは 30/48/15（＋unknown 3）。
- 「地形複雑度 低・中・高 各32」→ データに複雑度の項目がない。基準コストがマップサイズで決まるため、「複雑度」は実質マップサイズと同じ。
- 「各シナリオ3回実行、計288回」→ 結果は各シナリオ1回分のみ。
- 評価式 f=g+h+w_t·t(n)（w_t=1.0）→ 実装は g に「距離×(1+0.3(t−1))」を累積、ヒューリスティック1.5倍、枝刈りあり。
- シナリオのシードに `hash()` を使っており、実行のたびに値が変わる（手法間で同じマップだった保証がなく、再現できない）。

### 1.4 主張がデータで支えられていない
- 両方が成功した88シナリオすべてで、TA* と Theta* の経路長が完全に一致している（地形を考慮した効果が見えない）。
- 「TA* が最短」は、失敗したシナリオが平均から抜けた効果。4手法すべてが成功した88シナリオでは、Field D* Hybrid 20.40 m、TA* = Theta* 20.46 m、AHA* 20.74 m。
- 96シナリオのベンチマークに「地形コスト」が記録されていない。地形を考慮しない A* も比較に入っていない。
- 関連研究で `\cite` が0件。

## 2. `conference/` で作り直したもの

すべて再実行で再現でき、論文中の数値はスクリプトが自動生成します（手で書き写していません）。

| ファイル | 内容 |
|---|---|
| `tapp/terrain.py` | 4種類の地形（hills / ridge / craters / rocky）× 3スケール（50/100/200 m）。傾斜の中央値でスケールするので、サイズが違っても比べられる |
| `tapp/traversability.py` | 傾斜・粗さ・岩（ロボットの大きさ分だけ膨張）。**コストはロボットの限界値で正規化**（マップごとの最大値では正規化しない） |
| `tapp/planners.py` | A*、TA*（コスト d·(1+w·c) を g に累積、許容的ヒューリスティック → 最適性が保証される）、Lazy Theta*、コストを増やさない平滑化（TA*-S） |
| `tapp/metrics.py` | 全手法の経路を同じ方法で再サンプリングして評価（急斜面の走行距離、最大傾斜、登坂量、粗さ、エネルギー推定など） |
| `tests/test_planners.py` | A*/TA* が scipy の Dijkstra と同じ最適コストを返すこと、Theta* が A* より長くならないこと、平滑化でコストが増えないことを確認 |
| `experiments/run_all.py` | 検証用シードで w を選び（事前に決めた基準）、テスト用シードで評価。主比較、w の掃引、α のアブレーション、標高ノイズへの頑健性 |
| `experiments/analyze.py` | 対応のある Wilcoxon 検定＋Holm 補正＋効果量。表・図・数値マクロ（`paper/generated/numbers.tex`）を出力 |
| `paper/main.tex` | IEEE 会議形式の英語論文 |

再現手順（`conference/` で実行）:
```bash
pip install numpy scipy matplotlib pandas
python3 -m tests.test_planners
python3 experiments/run_all.py      # 4コアで約7分
python3 experiments/analyze.py
cd paper && latexmk -pdf main.tex
```

## 3. 本人にしかできないこと（投稿前にやってください）

1. **著者名・所属・学会名を入れる**（`paper/main.tex` の TODO 部分）。
2. **参考文献を出版社のページで確認する**（巻・号・ページ）。
3. **できれば実データで1例追加する**：BUNKER＋RTAB-Map で取った点群から標高マップを作れば、
   `TraversabilityMap(elev, rock)` にそのまま入れて同じ評価ができます。実データが1例あるだけで、論文の説得力が大きく上がります。
4. 卒論の Field D* Hybrid / AHA* は、今回の再実験には入れていません（元の評価が信頼できないため）。入れたい場合は、同じ評価の枠組みで測り直す必要があります。
